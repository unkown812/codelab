\section{Roadmap}
\label{sec:roadmap}

\textbf{Status:} all items RECOMMENDED or POTENTIAL unless marked EXISTING. Nothing below is a committed plan (no tracker exists in the repo).

\subsection{Existing (EXISTING)}
Embed playground with runtime switcher, configurable OneCompiler URL builder, 12 language guides, 4 blog guides, use-case/comparison/legal pages, SEO/AEO/GEO infrastructure (canonicals, OG, sitemap, JSON-LD, breadcrumbs, custom 404), lint+typecheck+CI gates, tokenized design system with icons, pruned template dead code, metadata-only favicon.

\subsection{Recommended next (RECOMMENDED)}
\begin{enumerate}
\item Align \texttt{buildOneCompilerSrc} and component defaults; add unit + render tests.
\item Add an embed-failure fallback message with retry guidance.
\item Set security headers/CSP at deploy time.
\item Add a dedicated 1200px OG share image (favicon is reused today).
\item Pin Node/npm versions (\texttt{.nvmrc} or \texttt{packageManager}) and document them.
\item Pin a known-good embed URL in documentation and add a periodic smoke check against \url{https://onecompiler.com/apis/embed-editor}.
\item Lift muted mono labels to AA contrast.
\end{enumerate}

\subsection{Potential future work (POTENTIAL)}
Optional, only if product direction demands: \texttt{postMessage} bridge exposing code-change/run events to CodeLab chrome, multi-tab editors, accounts/persistence (requires a backend design doc first), and a self-hosted editor to remove the third-party runtime dependency. Each would require new architecture, security, and testing documentation.
